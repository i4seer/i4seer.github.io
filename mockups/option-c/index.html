SHEET 02 · DEPLOYMENT 3 MODES
// destinations

Three ways to deploy.

Same device. Same firmware. Switching modes is one shell command on the device: cfg set base_url https://...

MODE 01
your stack

Bring your own backend

Point Tick at any HTTPS endpoint. JSON payload, HMAC-SHA256 signature header, predictable schema. Use Tick as a turn-key device fleet feeding your existing pipeline.

MODE 02
your server

Self-host our backend

Run our FastAPI portal on your own server. $4/mo droplet handles a meaningful fleet. Multi-tenant orgs and fleets, JSONL on disk, rsync for backup.

MODE 03 · DEFAULT
our server

i4Seer-hosted portal

Sign up at tick.i4seer.com, plug in the device, see live telemetry. We run the droplet, the TLS, the backups, the upgrades.

// transports

Pick the pipe per site.

WiFi for connected sites. Cellular for places without IT. Both for places where downtime hurts.

// 01 · sense often

Two independent cadences.

Sample every 30s, send every 30min. Each report carries lo / hi / avg / last for the window. A 30-second freezer spike still shows up as hi.

// 02 · lose nothing

Sensing decoupled from transport.

WiFi down, cell down, both down — the device keeps reading and folding values into the persistent NVS window. When transport recovers, the next send carries the full window.
