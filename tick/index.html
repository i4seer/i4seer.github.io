What Tick Is

Tick is a plug-and-play telemetry platform for monitoring distributed equipment. A small device sends HMAC-signed JSON over HTTPS to whatever endpoint you configure. Three transport modes — WiFi, cellular, or WiFi with cellular backup. Three destinations — your own backend, our backend on your server, or our hosted portal.


An AtomS3R + SIM7028 NB-IoT/LTE-M stack with an 0.85" IPS screen and a global Hologram SIM. Plug it in, pick a transport, point it at a URL, and it starts reporting telemetry within seconds. Out of the box, Tick reports to your i4Seer-hosted portal at tick.i4seer.com. Reconfigure with one shell command (cfg set base_url https://...) to point anywhere else.

Pick a Transport

Three modes. Same device, same backend, same dashboard. Choose per site.

MODE 1

WiFi Only

For connected sites: offices, kitchens, warehouses with reliable WiFi. No cellular cost, no SIM. WPA2/3, NVS-stored credentials, NTP-synced clock. Fastest pipe (sub-1s round trip), zero monthly per-device fee.

MODE 2

Cellular Only

For sites without IT: rentals, jobsites, mobile units, remote outbuildings. Ship the device, plug it in, it works. NB-IoT/LTE-M with a global Hologram SIM. 95%+ US/EU coverage. First reading in ~30 seconds.

MODE 3

WiFi with Cellular Backup

For sites where downtime hurts: pharma cold-chain, food service, anything regulator-watched. Tries WiFi first to save cellular cost, falls through to cell on any failure — per send, not per session. An ISP outage can’t take you offline.

What Makes It Different

None of these is unique on its own. The combination is rare.

Three Transports, One Device

WiFi, cellular, or WiFi with cellular backup — configurable per device. Same hardware, same firmware, same dashboard. Pick the transport that fits the site instead of buying different products for different deployments.

Per-Send Failover

In WiFi+cellular-backup mode, the device tries WiFi first and falls through to cell on any failure — per send, not per session. A brief router outage doesn’t cost you a dropped reading. 8s WiFi timeout, 60s skip-window after 3 fails.

Endpoint-Agnostic

Tick posts HMAC-signed JSON to any HTTPS endpoint. Use our backend (self-hosted or i4Seer-hosted) or your own. No proprietary protocol, no vendor SDK, no lock-in. Switching destinations is one shell command on the device.

Multi-Tenant from Day One

Real org / fleet / role model — not an afterthought. Inspectors with cross-customer access, contractors locked to one fleet, platform admins separated from regular users. Org is the security boundary.

HMAC Auth, No Key Registry

Device identity is derived from MAC. Reflashing or factory-reset doesn’t break identity. The HMAC secret is derived from MAC + per-fleet salt — no per-device key registry. Compromise is recovered by rotating one fleet salt.

Screen + QR on the Device

0.85" IPS screen on the front. Scan the QR with your phone, open the dashboard for that exact device. Multi-screen UI for field diagnostics: identity, WiFi, cell, data, send, scan. No app required to see if a device is healthy.

From Power-On to First Reading

Seven numbered steps. Boots in ~5 seconds. First reading lands in ~30.

[1/7]  host         ESP32-S3 info
[2/7]  wifi         associate (skipped if wifi_on=false)
[3/7]  modem        AT over UART
[4/7]  sim          CPIN ready + IMEI/CCID/IMSI
[5/7]  network      CEREG HOME or ROAMING (60s budget)
[6/7]  pdp attach   APN + IP
[7/7]  state        one state POST to the backend

Steps run in order with retry budgets per step; the device keeps making progress through transient failures rather than giving up. Sensing continues regardless of transport state — readings fold into a persistent accumulator (see below) so a WiFi or cell outage never costs you sensor data, only the moment it gets reported.

Sense Often, Report Smart

A naive sensor either samples too rarely (and misses short events) or floods the backend with raw readings. Tick does neither. Sample as often as the use case needs — accumulate the values — report a compact summary on a separate cadence.

Two Independent Cadences

Sample interval (how often to read the sensor) is independent of send interval (how often to ship). Sample every 30 seconds, send every 30 minutes — one record summarizes 60 readings.

Lo / Hi / Avg / Last

Each report includes the minimum, maximum, average, and most-recent value over the window — plus the timestamps of the first and last reading. A 30-second freezer spike inside a 30-minute window still shows up in hi.

NVS-Persistent

The accumulator lives in non-volatile storage. Power blip, modem reboot, MCU restart — the rolling window survives. The next report still reflects what happened during the outage. Sized for 20+ years of writes at 1-minute cadence.

No Reading Lost

Sensing is decoupled from transport. WiFi down, cell down, both down — the device keeps reading and accumulating. When a transport recovers, the next send carries the full window. The only thing an outage costs is the moment the data lands, not the data itself.

10-Second Server Buffer + Dedupe

The backend buffers writes for 10 seconds and dedupes by (device_id, tick). A cellular retransmit looks identical to the first send and gets coalesced — no double-counting, no special idempotency-token plumbing on the device.

Backend-Tolerant Schema

Payload is JSON. Adding a new metric means appending a field; older backends ignore unknowns. Storage is JSONL on disk — schema-flexible by design. Custom probes don’t require backend changes.

Hardware & Data

The Device

M5Stack AtomS3R (ESP32-S3, 8 MB PSRAM, 0.85" IPS, BMI270 IMU) on the Atom DTU NB-IoT2 v1.1 (K059) base with a SIM7028 modem and a global Hologram IoT SIM. USB-C power. Credit-card-sized.

Hardware spec sheet →

Identity from MAC

Device ID is T-<6 hex of last 3 MAC bytes> — e.g. T-BE04B8. Survives NVS wipe, reflash, and factory reset. No per-device secrets to manage.

WiFi + Cellular Hardware

The device has both pipes built in. ESP32-S3 native WiFi (WPA2/3, NVS-stored credentials). SIM7028 in NB-IoT mode with modem-side TLS. NITZ syncs the clock on cell; NTP fallback over WiFi (carriers block UDP/123). Pick which pipes are enabled per device.

JSONL on Disk

Telemetry is one JSONL file per device per UTC day. State snapshots are atomic JSON files. 10-second write buffer with (device_id, tick) dedupe handles cellular retransmits. Backups are rsync /var/tick/data/.

HMAC Auth

HMAC-SHA256 on every POST. Device secret is derived from MAC + per-fleet salt — no key registry on the server. Single combined X-Tick-Auth header (modem AT quirk: literal CRLF in headers gets sent raw). TLS underneath, RSA-2048 cert.

Honest Latency

Cellular RTT ~3-7s over NB-IoT. WiFi RTT under 1s when reachable. State snapshots refresh every 30 minutes by default. Reading cadence is configurable per device.

What’s Next

Tick ships data reliably from anywhere with cell coverage. The alerting layer that turns that data into a pager is being built now.

Server-Side Alerting

Fleet-level rule engine, email and webhook channels, dwell-time + cooldown, resolved-notifications. The “page at 3am” feature. Building now.

External Sensors

Today readings are the device’s own MCU temperature — a self-monitoring metric. DS18B20 customer-temperature probe (1-Wire, waterproof, ~$2) is the first external sensor on the path.

Email Password Reset

Today password resets are admin-driven. Self-service reset via email token is on the path before the first paying customer.

Off-Droplet Backups

Today backups are manual rsync. Nightly rsync to S3-compatible (Backblaze B2 or DO Spaces) is queued for the first fleet that can’t afford to lose data.
