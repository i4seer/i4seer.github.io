Live device view.

Per-device dashboards that update on a one-second tick. Every reading shows which transport carried it, how long the round-trip took, and how healthy the device is right now.

At a glance

Card grid · live tick

Every device the user can see, grouped by org. Status pill, last-seen relative time, countdown to the next scheduled send — all updating in real time without a page reload.

Per device

Transport, signal, sends/fails

WiFi up/down + SSID/RSSI/IP, cell up/down + CSQ + registration, sends and fails per transport, switches counter. Admin-off pipes show a dash so “down” never reads as a fault.

Per reading

Via · latency · uptime

Multi-tenant from day one.

Real org / fleet / role model. The same identity can be editor in one org and viewer in another. Inspectors with cross-customer access, contractors locked to one fleet, platform admins separated from regular users.

Org

The security boundary

Every device belongs to 0 or 1 orgs. Data is partitioned per-org on disk and in the dashboard. Cross-org leakage is structurally impossible, not just policy-bound.

Fleets

Groupings within an org

“Building A,” “Pilot customers,” “Bench” — whatever you want. Devices can live in multiple fleets at once. Fleets are for visibility and access, not ownership.

Roles

Owner, editor, viewer, fleet member

Per-org roles cascade across fleets. Fleet members opt out of the cascade for outside-contractor scoping. Viewers can be elevated to editor on a specific fleet without org-wide permissions.

Remote console.

Reach any device through your dashboard, in real time, from any browser. Same shell as standing at the bench with a USB cable — only it’s a fielded unit on a tower across town.

Open in seconds

Click. Pick. Type.

Click Open Session, pick the device, type. Sessions go live in about two seconds on WiFi, five on cellular. xterm.js terminal, ANSI colors, scrollback — everything you’d expect.

Multi-operator

More than one admin can attend

Multiple admins can attach to the same session at the same time. They see each other’s commands and the device’s responses live, with each command tagged by the submitter’s email.

Transport-aware

Choose the route per session

Open on WiFi to save cellular minutes; switch to cellular mid-session if WiFi drops. The chosen transport accelerates for responsiveness; the other stays at idle.

Auto-end

Walk away safely

Sessions end automatically two minutes after the last activity from either side. Full transcript saved server-side, visible later from the audit log. No leaked sessions, no forgotten terminals.

USB mode

Same console, plugged in

For benches and provisioning. WebSerial in Chrome / Edge desktop. Auto-reconnect on page reload and on USB plug-in. Same xterm.js, same color scheme, same line-ending controls.

Default-deny allowlist

Locked-down by design

The remote console can only run commands explicitly whitelisted on the device. Lockout-class commands prompt a UI confirmation; the device-side allowlist is the real boundary.

Audit-by-default.

Every state-changing action is recorded with actor, IP, target, and detail. Org members see their own org’s history; platform admins see global events. The wire is signed both ways — HMAC out of the device, HMAC back from the cloud.

Per-org audit

Every approval, label, session

Approve a device, change a label, open a console session, eject from a fleet — all logged with operator identity, timestamp, and full detail. Click any row to expand the kv body.

Bidirectional HMAC

Signed both ways

Device requests carry HMAC-SHA256 of body + timestamp + nonce. Server responses are signed back with the same secret + the request’s nonce. A captured response can’t be replayed; a forged request can’t pass.

Salt rotation

No-downtime key rotation

Backend accepts both current and previous salt for a configurable window. Rotate without firing a healthy fleet into a recovery hole. HMAC mismatch from a typo auto-recovers in ~6 minutes.

Device lifecycle.

Five clean states, one unified verb for moving devices between them. A factory-fresh device lands in the unclaimed pool, gets assigned to an org, lives there until you eject it, and shows up in the next org’s pool with a hint about where it came from.

Pending

Brand-new, never claimed

Sits in the unclaimed pool. POSTs are accepted but no data is persisted. ICCID-derived label so a freshly-claimed device isn’t anonymous.

Approved

In an org, persisting data

POSTs persist, data shows in dashboards, the device participates in fleet membership and audit. Editor and above can rename or move it.

Disabled / Ejected

Suspended or kicked out

Disabled: POSTs rejected with 403, no data written, recoverable. Ejected: returned to the unclaimed pool with a previously_in_org hint. Historical visibility preserved via “show released.”
