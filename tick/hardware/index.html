HARDWARE

Credit-card-sized. USB-C powered. ESP32-S3 + SIM7028 NB-IoT/LTE-M modem + global Hologram SIM. Ships first reading in ~30 seconds.

The Stack

AtomS3R (top)

ESP32-S3 with 8 MB PSRAM. 0.85" 128×128 IPS display. BMI270 6-axis IMU. BMM150 3-axis magnetometer. Front button cycles screens. PSRAM-OPI flash mode.

Atom DTU NB-IoT2 v1.1 (K059, base)

SIM7028 NB-IoT/LTE-M modem on the standard Atom socket. SMA antenna connector, SIM slot, USB-C power passthrough. The board the AtomS3R clips on top of.

Hologram Global IoT SIM

Default APN hologram. Pay-as-you-go data, no minimum, no carrier contract. Works in 200+ countries. Swap to another carrier’s SIM and change one APN line in firmware to switch.

Key Facts

Identity from MAC

Device ID is T-<6 hex of last 3 MAC bytes> — e.g. T-BE04B8. Survives NVS wipe, reflash, and factory reset.

0.85" IPS Screen

Multi-screen UI: identity, WiFi, cell, data, send, scan. Front button cycles. 30s auto-revert. [!] indicator stays lit when boot is in failed state.

Modem-Side TLS

SIM7028 handles TLS via AT+CSSLCFG + AT+HTTPACTION. No CA bundle on device — HMAC at the application layer is the auth, TLS is line-tap protection. RSA-2048 cert (modem doesn’t accept ECDSA).

Boot in 5s, First POST in 30s

Cold boot to first state POST is dominated by NB-IoT attach. Cellular RTT after attach: ~3-7s over NB-IoT. WiFi RTT: under 1s.

NVS-Backed Counters

Tick number, accumulator (count, lo, hi, sum, last), epoch timestamps. Per-minute readings fold into the accumulator; RAM seq resets on boot. NVS partition sized for 20+ years at 1-min cadence.

QR Deep-Link

Each device renders a per-device QR on the screen. Scan with a phone, opens the dashboard for that exact device. No paperwork, no part numbers.

Power Modes

PSM and eDRX both work on Hologram/T-Mobile US — requested timers granted as-requested. AT+CSCLK auto-sleep modes return ERROR on this firmware revision; host-only light-sleep is the fallback.

Diagnostic Shell

USB serial at 115200. Type help for the command list: start, send, cfg, wifi connect, reboot dtu, scan, etc.

What It Measures — Today

Today the device reports its own MCU temperature — a self-monitoring metric, not a customer-facing one. That’s honest about where the product is.


External sensors are the next hardware step. DS18B20 (1-Wire, ~$2, ±0.5°C, waterproof variants for fridges/freezers) is the obvious first pick. Wires to a free GPIO on the Atom socket; firmware adds probe_lo / probe_hi / probe_avg / probe_last fields to the payload. Backend already tolerates unknown fields — JSONL is schema-flexible.


If you need a different probe (humidity, current, pressure, contact, pulse-counting), tell us — we’ll spec the integration during pilot.

Enclosure & Mounting

The dev-board form factor works for pilots. For production: enclosure (waterproof if outdoor), mounting (magnet, screw, or zip-tie), clear label with claim token + serial, and a one-page quickstart card.

M5Stack ships matching cases for the AtomS3R. We’ll spec enclosure + cable routing alongside the first real customer deployment — cost-of-goods conversation, not a commodity SKU.
