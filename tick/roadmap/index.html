i4Seer / Tick / Roadmap

What ships today. What’s next.

Honesty is a positioning advantage. We don’t list features as shipped until they actually ship. Here’s where things actually stand.

Shipping today.

If we say it on the main page, it works in production. Live at tick.i4seer.com.

Live Shipped

Cellular + WiFi

Both transports run continuously. WiFi-first dispatch with cell fallback. Auto-recovery from outages without operator action.

Live Shipped

Three deployment modes

Bring your own backend, an enterprise Tick Private Portal, or the i4Seer-hosted portal. Same firmware behind all three.

Live Shipped

Multi-tenant orgs

Real org / fleet / role model. Inspectors with cross-customer access. Contractors locked to a single fleet. Platform admins separated from regular users.

Live Shipped

Remote console

Open a terminal session to any device through your dashboard. Real-time output, multi-admin sessions, full transcripts saved to audit.

Live Shipped

Per-device dashboard

Live transport indicator, signal strength, send/fail counters per transport, snapshot age. Mobile-responsive.

Live Shipped

Auto-provisioning

Factory-fresh devices land in the unclaimed pool with auto-named labels. Platform admins assign to an org with one click.

Live Shipped

Per-org audit log

Every approval, label change, and console session logged. Members read their own org’s history. Platform admins see global events.

Live Shipped

Public read-only fleet

One operational fleet exposed at /public, field-scrubbed and rate-limited. The demo is the product.

Building now.

Active priorities. These are the next features customers will see.

In progress Coming

Server-side alerting

Fleet-level rules. Email and webhook delivery. Threshold breaches, dwell-time, cooldowns, resolved-notifications. The pager-at-3am feature.

In progress Coming

Routes

The portal forwards data and state changes out to your destinations as they arrive. HTTPS routes ship first; other targets are in development:

  • HTTPS Coming soon
  • MQTT In dev
  • AWS In dev
  • Azure In dev
  • Google Cloud In dev
  • Twilio In dev
  • Datacake In dev
  • Blynk In dev
  • Qubitro In dev
In progress Coming

External temperature probes

1-Wire DS18B20 first — cheap, accurate, waterproof. Measure what your customer actually cares about, not the device’s internal temperature.

In progress Coming

Email-driven password reset

Self-service reset over email token. On the path before self-service onboarding for new orgs.

In progress Coming

Off-server backups

Nightly automated backup to S3-compatible storage. Cheap, decoupled from any single server’s survival.

In progress Coming

Dashboard config UI

Edit reading cadences, send intervals, and the auto-reboot schedule from the device’s page. Today: terminal-only.

Later.

On the list, but waiting for a customer to ask. We don’t speculatively build.

Self-service claim tokens

Customer enters a one-time token printed on the device label and the device joins their org. Today: a platform admin clicks Approve.

Charts on device detail

Trend lines, range pickers, threshold overlays. Most useful once alerting overlays its rules on the same chart.

OTA firmware updates

USB updates work for any device we can physically reach. Build OTA when there’s a fleet that can’t be reached.

Stripe billing

Per-device-per-month, billed to org owner. Won’t exist until someone’s offered to pay.

Device-went-dark detection

The other half of alerting: a device that should be reporting and isn’t. Same plumbing as threshold alerts, different trigger.

Scale to a real database

The current file-based store is fine to a few thousand devices. Beyond that, time-series indexing alongside. Files stay valid through the transition.
